# CNMCP 页面与样式规范 v2.0（普通用户定稿）

## 直接执行

### 页面结构

全站按三层组织浏览，不是父子节点：

1. **固定栏目**：全部 / 主题 / 资源发现，与 Logo 同行，使用轻量下划线表示选中；顶部固定。
2. **领域与分类**：领域位于列表容器顶部。主题页下一行显示适用的平级节点；资源发现页下一行显示适用标签，两者复用同一水平文字导航组件、字号和选中样式。领域与分类共用白色表面，无中间分割线、独立卡片或大间距。
3. **全部概览**：仅显示领域导航，按“最近讨论”（最多 6 条）和“资源发现”（最多 3 条）分区，提供“更多主题”“更多资源”入口。无混排、节点、标签、统一排序或分页。两区单独按最新内容排序。

没有独立强制选择页，默认浏览全部领域。概览页忽略旧链接中的节点、标签及其隐式条件；进入概览或通过“更多”进入完整列表时保留领域、清除分类。主题页按领域及节点筛选，资源页按领域及标签筛选。两类分类的视觉一致不改变数据归属。

所有浏览页移除左侧标签栏。资源发现移除页内搜索及隐藏的旧 q 条件，保留类型和排序；全站顶部搜索继续提供统一搜索入口。

资源详情复用同一资源ID，不按领域拆分评论。发布页保留全站导航，表单仍为标题/选填正文/单领域与单节点，领域栏是浏览上下文，表单选择是当前主题归属。

### 关键路径

| 页面 | 路由示例 | 模块 |
| --- | --- | --- |
| 主题 | #/?view=topics&domain=video&node=qna | 领域/节点、筛选摘要、排序、列表、分页、参与侧栏 |
| 主题详情 | #/topic/offline | 领域与节点浏览入口、正文、资源引用、开放回复、反馈 |
| 资源发现 | #/resources?tag=python | 多标签入口、类型下拉、搜索、排序 |
| 资源详情 | #/resource/comfyui | 来源/用途、Star与站内互动、独立评论、反向主题 |
| 发布/编辑 | #/publish?domain=game&node=qna | 标题、选填正文、预览/@引用、领域/节点两个下拉、草稿 |
| 指南 | #/guide?tab=nodes | 领域与节点规则、适用矩阵、资源标签边界 |

搜索、工作台、通知与设置维持普通用户模块，数据引用同步领域与节点两个字段。

### 发布与联动

连续表单：标题 → 正文/预览及引用工具栏 → 领域下拉、节点下拉 → 发布/草稿。不添加内容类型或常驻资源选择区。先选领域再选节点；共享节点在切换领域后保留，专用节点不适用则清空并以提示说明。分类未完成可存草稿，公开发布必须有效。

### 视觉变量

沿用系统中文字体、13–14px正文、10–12px元信息；最大1120px容器、248px侧栏、18px间距、5px模块圆角。背景#e9eaec、纸面#fff、文字#354052、辅助#647084、边线#e4e8ef、蓝色#466aa4。深色使用同一组语义变量。

### 响应式与状态

780px及以上右侧显示社区侧栏；520–779px时移到主列表下方以两列排列，手机单列显示。700px以下主栏目和全站搜索分别换行；领域与节点/标签紧凑排列，分类自然换行；列表占满主内容宽度，无左侧标签栏。发布领域与节点下拉改为两行，引用弹层维持共享组件。表单错误、不适用提示、空、加载、隐藏、未登录状态保留输入并可继续。

## 深度交互

领域不是节点父级。视觉上的上下两行用于先后筛选，全部领域下的问与答仍是一个节点；不生成多棵领域节点树。明确专题优先具体节点，综合问答使用通用节点，避免单选归属因说明不足而变得随意。

资源卡显示关联领域与当前领域标签，详情保留统一的来源、评论与质量信号。普通用户不直接管理资源分类；首版领域与标签绑定来自版本化配置和来源清单。新链接未分类时在全部领域可见，不显示资格等级。

### 社区右侧栏

参考 V2EX 的紧凑白色用户卡片、细分隔线和短列表。四个固定模块：

1. 用户信息：未登录展示简介、体验登录和指南；已登录展示昵称、收藏/关注/主题数量、未读提醒与设置入口。关注数量进入工作台的关注主题页。
2. 参与入口：创作新主题、当前领域的等待回应数量。
3. 今日热议：当前领域最多 5 条有当日可见回复的主题，按当日回复数排序，平局按主题时间；无互动时提供待回应入口。已知示例数据仅在当前预览会话模拟日期并标记演示，新回复使用实际时间。
4. 最近浏览：实际打开的主题与资源，按 kind+ID 去重，保留 20 条，显示最新 5 条；跨领域保留，刷新持久化，隐藏/删除目标不显示。清空仅影响本浏览器记录。

共同侧栏用于所有标准 Layout 页面，详情页原有上下文模块追加在后。主题、资源和工作台的分类及评论模型不变。

### 普通用户定稿边界

登录弹窗只提供普通成员体验；工作台、设置和全站导航不含运营角色切换或内容管理入口，旧管理路由不可用。反馈只显示普通用户提交回执。生产权限、表结构和项目归属以 PRD 2.0 与架构文档为准。
