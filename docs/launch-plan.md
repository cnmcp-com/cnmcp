# CNMCP 快速上线任务规划

目标：优先交付“能浏览、能理解、来源可追溯”的公开目录，再逐步扩大动态验证覆盖率。

## P0｜上线前必须完成

| 任务 | 验收标准 | 当前状态 |
| --- | --- | --- |
| 清理聚合来源链接 | 页面不再展示“查看收录页”及腾讯云来源页链接，保留可核验的代码仓库链接 | 已完成 |
| 首页与品牌升级 | 首屏一句话说明核心用途，搜索和精选资源进入首屏；品牌锁定包含正式图标和产品定位 | 已完成 |
| 评分表达统一 | 公开证据完整度作为主指标，动态验证仅显示为辅助状态；默认按证据完整度排序 | 已完成 |
| 来源说明排版 | README 具备清晰标题层级、正文行距、列表和代码块样式，并声明内容边界 | 已完成 |
| GitHub 变更扫描 | 定时扫描仓库推送时间、归档状态和默认分支，写入资源变更历史 | 已完成代码，待生产迁移与令牌配置 |

| 生产验收 | 应用迁移、构建、类型检查、核心页面及 Cron/Queue 冒烟测试全部通过 | 迁移与本地构建已完成，待线上发布验收 |

## P1｜上线后第一周

1. 观察 GitHub API 限额与扫描覆盖率，确保全部 GitHub 来源在目标周期内至少扫描一次。
2. 为验证队列增加死信队列和失败告警，避免任务达到重试上限后静默丢失。
3. 完成 Remote MCP 动态实测覆盖；本地 `stdio` 资源继续明确显示“待实测”。
4. 根据搜索词和目录点击数据调整首页精选规则，不引入付费排序。

## P2｜稳定后迭代

1. 为 GitHub 扫描增加 Release、README 和许可证变化检测。
2. 部署隔离的 `stdio` 探测节点，支持受控的 npm、Python 启动器。
3. 增加发布方申诉、变更订阅和公开验证报告导出。
