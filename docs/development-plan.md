# CNMCP 页面与数据表达优化计划

## 目标

把现有 994 条资源的静态检查、动态验证、发布方和来源数据，转化为用户能正确理解和筛选的产品信息。核心原则是：静态证据与动态验证分开表达，不把“未完成动态验证”误写成“不可信”。

## P0：统一验证语义（本轮必须完成）

- 全站区分“动态验证分”和“静态证据分”。
- 详情页、卡片、方法论和提示文案使用同一套术语。
- 页头同时显示动态验证数量和资源总量。
- 验收：任何只有静态证据的资源都不会被描述为“已动态验证”；页面不再出现“展示分数”与“不给分数”的矛盾文案。

## P1：提高目录查找效率（本轮必须完成）

- 增加动态已验证、静态已检查、动态未完成三类状态筛选。
- 增加动态验证分、静态证据分、最近验证、可信方优先四种排序。
- 卡片明确标注当前圆环展示的是哪类分数。
- 验收：筛选和排序由 API/数据库执行，分页结果与总数一致。

## P2：让报告和动态页由真实数据驱动（本轮必须完成）

- 扩充统计接口：可信方发布、静态检查、配置覆盖和各状态数量。
- 报告页展示动态验证覆盖率、数据覆盖缺口和状态分布。
- 安全动态页展示数据库中的最近验证与变更事件，移除长期空白占位。
- 验收：页面数字全部来自本地数据库，无手写样例统计。

## P3：补齐入口与提交体验（本轮尽量完成）

- 主导航加入数据报告，验证动态名称与内容一致。
- 配置体检移除伪进度，增加即时 JSON 状态和本地文件读取。
- 提交页增加提交类型、前端校验、处理流程与回执编号。
- 验收：用户能理解数据会如何处理；配置内容不上传。

## P4：减少无来源数据并强化资源价值（2026-09-24）

- 暂时移除没有可靠关联算法的同类推荐。
- 暂时隐藏定价、付费、许可证等缺少可靠数据来源的字段和筛选项。
- 来源页与代码仓库提供明确的外部跳转。
- 首页首屏直接展示真实资源，搜索增加明确按钮和常用搜索入口。
- 配置体检加入传输加密、URL 凭证、Shell 执行、依赖版本、宽泛权限、TLS 校验和重复端点等本地规则。
- 页面可见术语优先中文化，协议原始证据保留必要英文。
- 增加详情页结构化数据、面包屑和更明确的独立标题描述。
- 验收：页面不再用“未知”字段占据主要空间；所有可见结论都有明确来源或检测规则。

## 验证门槛

- schema、API、checkers 测试通过。
- 全仓类型检查通过。
- 首页、目录、详情、报告、验证动态、配置体检、提交、方法论完成桌面端页面回归。
